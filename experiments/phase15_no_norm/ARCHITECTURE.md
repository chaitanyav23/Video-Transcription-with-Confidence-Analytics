# Phase 15 Architecture: No-Normalization Pipeline

## Structural Design
Phase 15 implements a linear, stage-based pipeline optimized for high-accuracy transcription and diarization. The architecture is "hardened," meaning it uses fixed, high-performance models and grounded transitions between stages.

### 1. Preprocessing Layer
- **Audio Repair (FFmpeg):** Standardizes input to 16kHz, mono, PCM S16LE. This is the only preprocessing step.
- **No Normalization:** Unlike standard production branches, no gain control or peak normalization is applied.

### 2. Segmentation Layer (VAD)
- **Model:** Pyannote 3.1 VAD.
- **Function:** Generates the "grounding" segments. These segments define the regions where the ASR and Diarization models will focus their analysis.
- **Parameters:**
  - `merge_gap`: 0.15s
  - `min_duration`: 0.1s

### 3. ASR Layer (WhisperX)
- **Model:** Whisper `large-v3`.
- **Execution:** Segment-wise transcription. The VAD segments are used to slice the audio before it is passed to the Whisper model.
- **Alignment:** Phoneme-level alignment using Wav2Vec2-based models to generate precise word-level timestamps.

### 4. Diarization Layer (NeMo MSDD)
- **Model:** NeMo Multiscale Diarization Decoder (MSDD).
- **Speaker Embeddings:** TitaNet-Large.
- **MSDD Config:** `diar_msdd_telephonic`.
- **Logic:** Operates in "Oracle VAD" mode, where it uses the segments generated by Step 2. This isolates the speaker labeling performance from the VAD performance.

### 5. Fusion Layer
- **Logic:** Time-based overlap matching.
- **Tolerance:** 0.5s for nearest-neighbor fallback.
- **Output:** A combined JSON/TXT transcript where each word is attributed to a specific speaker ID discovered by MSDD.

## Hardware & Environment
- **Compute:** CUDA-accelerated (NVIDIA GPU).
- **Frameworks:** PyTorch, NeMo, WhisperX, Pyannote.Audio.
- **Storage:** Local filesystem for intermediate manifests, RTTMs, and JSON outputs.
