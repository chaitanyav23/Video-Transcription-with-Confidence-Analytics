# MSDD CONFIGURATION AUDIT (PHASE 11A)

This audit analyzes the exact configuration of NeMo's Multi-scale Diarization Decoder (MSDD) as implemented in Phase 11A (`experiments/phase11_dfn_ablation/step3_run_pipelines.py`).

## 1. SPEAKER COUNT LOGIC

### Why was `num_speakers` fixed to 2?
In the Phase 11A script, the speaker count is hardcoded to 2 in the manifest generation:
```json
"num_speakers": 2
```
This was likely a research simplification for the BWC dataset, which primarily contains 1-on-1 officer/subject interactions. However, the configuration also enables `oracle_num_speakers: True`, which tells NeMo to trust the value provided in the manifest.

### Does MSDD support automatic speaker count inference?
**YES.** To enable automatic inference, the following code changes are required based on the NeMo API:
1. Manifest `num_speakers` must be set to `null` (None).
2. `oracle_num_speakers` must be set to `False`.
3. `max_num_speakers` must be defined to cap the clustering search.

Evidence from `run_karen_audit.py` shows this transition:
```python
"max_num_speakers": 5, 
"oracle_num_speakers": False
```

## 2. CONFIGURATION PARAMETERS AUDIT

| Parameter | Value in 11A | Verified Status | Impact |
| :--- | :--- | :--- | :--- |
| `oracle_vad` | `True` | **ACTIVE** | Bypasses MarbleNet; uses injected RTTM boundaries. |
| `oracle_num_speakers` | `True` | **ACTIVE** | Forces the model to use the count in the manifest. |
| `max_num_speakers` | `2` | **ACTIVE** | Caps the clustering output. |
| `max_rp_threshold` | `0.25` | **ACTIVE** | Controls clustering sensitivity. |

## 3. RTTM INJECTION & "ORACLE" VALIDATION

### Does the RTTM injection path work when speaker count is unknown?
**YES, but with specific behavior.**
When `oracle_vad: True` is set and an RTTM is injected:
1. MSDD uses the RTTM boundaries for segmenting the audio.
2. If `oracle_num_speakers: False`, the model will extract embeddings from those segments and perform clustering to determine the speaker count automatically.
3. The injection successfully skips the `MarbleNet` VAD stage, which was the primary source of timeouts in earlier phases.

### Misuse of "Oracle" Terminology
The audit confirms that the term "Oracle" in Phase 11A does **NOT** refer to human ground truth. 
* It refers to **System VAD boundaries** generated by Pyannote 3.1. 
* These boundaries are injected into NeMo as a "perfect" reference to bypass its internal VAD failures.

## 4. LIMITATIONS IDENTIFIED
* **Hardcoded Manifests:** The Phase 11A script generates a manifest with `num_speakers: 2` for every file. If this script is run on an audio file with 4 speakers, the output will be forced into 2 clusters, causing catastrophic "Speaker Confusion" errors.
* **Manual Manifest Writing:** The data flow relies on `json.dump` to a temporary file before model instantiation, which adds I/O overhead and complicates multi-file parallelization.
